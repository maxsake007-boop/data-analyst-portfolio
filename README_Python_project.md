Автоматизированный скрипт первичной обработки и очистки сырых транзакционных данных розничных продаж (**Retail Sales**) перед загрузкой в реляционную базу данных (PostgreSQL / DWH) или BI-систему (Power BI).

---

## 📌 О проекте и бизнес-задаче

В реальном бизнесе выгрузки из учётных систем (CRM, ERP, 1C, веб-витрин) часто содержат человеческие и аппаратные дефекты: дублирование чеков при повторных транзакциях, разнобой в форматах дат, текстовые ошибки ввода, отрицательные значения из-за технических сбоев и пропуски в реквизитах.

**Цель пайплайна:** превратить исходный «грязный» файл `dirty_sales.csv` (5000 строк) в полностью валидированный датасет `clean_sales.csv`, готовый к аналитике и расчёту бизнес-метрик (выручка, средний чек, динамика продаж).

### Структура данных:
| Колонка | Исходный тип | Тип после обработки | Описание |
|---|---|---|---|
| `order_id` | `object` | `str` | Идентификатор заказа |
| `order_date` | `object` (разные форматы) | `datetime64[ns]` | Дата совершения покупки |
| `customer_name` | `object` (грязный регистр) | `str` | Имя и фамилия покупателя |
| `region` | `object` (пропуски, пробелы) | `str` | Регион доставки/продажи |
| `category` | `object` (разнобой регистра) | `str` | Товарная категория |
| `product_name` | `object` | `str` | Наименование товара |
| `quantity` | `int64` (были `< 0`) | `int64` | Количество единиц (только `> 0`) |
| `unit_price` | `float64` (были `< 0`, `NaN`) | `float64` | Цена за единицу (только `> 0`) |

## 🔍 Подробный разбор этапов пайплайна

Код скрипта выстроен по принципу линейного и читаемого конвейера (ETL):

### Блок 1. Загрузка данных
```python
df = pd.read_csv('dirty_sales.csv')
```
*Загружает сырой CSV-файл в объект DataFrame для последующей обработки в оперативной памяти.*

---

### Блок 2. Первичный исследовательский анализ (EDA)
```python
print(df.head(5))
print(df.info())
print(df.describe())
```
* **`head(5)`**: быстрый визуальный осмотр структуры первых строк.
* **`info()`**: контроль типов данных, объёма памяти и первичного наличия `Non-Null` значений.
* **`describe()`**: математическая статистика числовых признаков (`quantity`, `unit_price`). Позволяет мгновенно обнаружить отрицательные минимальные значения (`min < 0`), указывающие на логические аномалии.

---

### Блок 3. Стандартизация названий колонок
```python
df.columns = df.columns.str.strip().str.lower()
```
* Защита от случайных краевых пробелов в заголовках таблиц (`' order_id '` ➔ `'order_id'`).
* Приведение к единому нижнему регистру для соответствия стандартам баз данных (SQL / PostgreSQL).

---

### Блок 4. Анализ и нормализация форматов дат
```python
# Маскирование цифр для выявления уникальных шаблонов дат:
print(df['order_date'].str.replace(r'\d', 'X', regex=True).value_counts())

# Конвертация в тип datetime:
df['order_date'] = pd.to_datetime(df['order_date'], dayfirst=True, format='mixed')
```

#### 💡 Аналитическое примечание к этому шагу:
В сыром наборе часть дат была записана по стандарту ISO (`2023-08-11`), а часть - в европейском формате со слэшами (`19/01/2024`).

1. **Как выявлены форматы:** Выражение `str.replace(r'\d', 'X', regex=True)` заменяет любую цифру на символ `X`, проявляя каркас даты (`XXXX-XX-XX` и `XX/XX/XXXX`). Это позволило сразу увидеть распределение форматов через `value_counts()`.
2. **Альтернативный подход через цикл:** Эту же задачу на чистом Python можно решить циклом `for` с проверкой вхождения разделителя (`if '-' in date: ... else: ...` - аналог SQL `LIKE '%-%'`). Однако векторизованный подход Pandas через регулярное выражение был выбран как более **лаконичный, производительный и масштабируемый**.
3. **Исправление:** Параметр `format='mixed'` позволяет разобрать смешанные шаблоны в рамках одной колонки, а `dayfirst=True` гарантирует, что первое число интерпретируется как день месяца.

---

### Блок 5. Дедупликация данных
```python
df = df.drop_duplicates()
```
*Устраняет 80 полных строк-дубликатов, возникших из-за повторных сетевых вызовов в источнике данных.*

---

### Блок 6. Фильтрация бизнес-аномалий (отрицательные значения)
```python
df = df[df['quantity'] > 0]
df = df[df['unit_price'] > 0]
```
* В транзакционном реестре чистых продаж отрицательные объёмы и цены недопустимы (возвраты оформляются отдельными корректировочными документами).
* Применена векторизованная булева фильтрация (`Boolean Indexing`), отсекающая строки с `quantity <= 0` и `unit_price <= 0`.

---

### Блок 7. Стратегия обработки пропущенных значений (NaN)
```python
# 1. Заполнение пропусков в регионах
df['region'] = df['region'].fillna('Unknown')

# 2. Удаление строк без цен
df = df.dropna(subset=['unit_price'])
```

#### 💡 Бизнес-логика разделения:
* **Почему для `region` применён `fillna('Unknown')`?** Заказ реален, деньги получены, товар отгружен. Удаление 154 заказов привело бы к искусственной потере десятков тысяч долларов реальной выручки. Маркировка `'Unknown'` сохраняет целостность финансового объёма.
* **Почему строки без `unit_price` удалены (`dropna`)?** Без цены невозможно рассчитать финансовые показатели (выручку, AOV). Подставлять среднее (`mean`) нельзя из-за высокой вариативности цен по каталогу (от 5\$ до 1500\$), а удаление 30 строк (< 1% данных) гарантирует чистоту финансовых метрик.

---

### Блок 8. Очистка строковых полей
```python
text_columns = ['customer_name', 'region', 'category', 'product_name']
for col in text_columns:
    df[col] = df[col].str.strip().str.title()
```
* **`str.strip()`**: удаляет случайные концевые и начальные пробелы.
* **`str.title()`**: приводит текстовые атрибуты к стандарту Title Case (первая буква заглавная). Устраняет проблемы разрозненного ввода операторов (`'electronICS'`, `'FOOD'` ➔ `'Electronics'`, `'Food'`).

---

### Блок 9. Хронологическая сортировка
```python
df = df.sort_values('order_date')
```
*Упорядочивает транзакции по возрастанию даты. Это стандарт для DWH и витрин данных, необходимый для корректного расчёта нарастающих итогов и оконных функций в SQL.*

---

### Блок 10. Контроль качества данных (Data Quality Check) и экспорт
```python
# Финальная валидация отсутствия пропусков и дубликатов
print(df.isnull().sum())
print(df.duplicated().sum())

# Сохранение чистого файла
df.to_csv('clean_sales.csv', index=False)
```
* Проводится финальный аудит (`Sanity Check`): дубликатов - `0`, пропусков - `0`, минимальные значения цен и объёмов строго положительны.
* Экспорт в `clean_sales.csv` выполняется с параметром `index=False`, чтобы исключить генерацию лишнего безымянного столбца индекса при импорте в СУБД.
